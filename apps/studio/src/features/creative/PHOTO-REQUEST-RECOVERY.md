# Studio photo request recovery

`photo-request-journal.ts` commits the exact prepared JSON body and stable operation key to IndexedDB before paid HTTP. Its active slot binds the authenticated actor, selected library, property, immutable master SHA-256, and prepared-input version SHA-256. It retains the actual master File unchanged and checks the context against the saved body. Concurrent tabs serialize get-or-create in one transaction and obtain the same operation key.

Unknown, pending, held, aborted and lost-response operations cannot be replaced by changed instructions or a new upload receipt. The current actor/library/property must still match before and after each asynchronous boundary. The fixed request controller sends only `/functions/v1/ai-photo-v2` with the typed `retained-operation-v1` capability, exact saved body and key; credentials come from the current authenticated services layer and are never journaled. API status and safe recovery details are retained without provider URLs or arbitrary headers.

A confirmed response is committed as a ready preview before the UI consumes it. Reload restores a ready preview without HTTP; pending work resumes the same operation. Single-photo and batch screens restore their own current-scope entries automatically, including the source and original upload identity. Unstarted batch slots are not manufactured on reload. Normal gallery save or an explicit new edit after a ready result can release the slot. Only a definite no-dispatch response or terminal quality refusal releases pending work; uncertain liability is never treated as a refunded/free edit.

Browser storage is local to this browser origin, not cloud backup. Storage failure before dispatch sends nothing; failure after an accepted supplier response keeps the pending identity for server reconciliation. The server remains the authority for current identity, input ownership, once-only generation/judge dispatch and costs. No original master, upload protocol, plan quota, funding grant or backend flag is changed by this client journal.

Focused checks: `tests/photo-request.test.ts`, `tests/data.test.ts`, `tests/creative-batch.test.ts`, and `tests/photo-recovery-browser.mjs`. The browser proof uses real IndexedDB, canvas images, the actual journal/controller and single/batch UI with isolated idempotent HTTP fixtures. It makes no hosted/provider calls. Existing Creative Studio and photo delivery/ZIP browser proofs also pass with their route assertions updated to include v2.
