# Findings — C · Data model, persistence, AppModel, Settings/Profile/AgentCard/Portfolio, Config, plists, project.yml

## Summary
The persistence layer itself is in good shape: relative paths, atomic writes, samples never persisted, tolerant field-by-field decoding for every persisted type, and all 40 Swift files + resources are in the Xcode target with a deployment target (16.0) that covers every API used. The hard rules hold (no compiled digital-goods prices in Money/Formatters/Render, entitlements = SIWA only, optional new fields).

The worst problems are in what the model *cannot* express or do: there is no delete-listing operation at all (drafts and mistakes live forever), a listing killed mid-render is stuck in "Working on it" with no way to render, publish, or remove it, `AppModel.renders` is never written so the chosen tier/AI options are lost, and every artifact a listing produces after the tour (aerial clip, floor plan, reels, enhanced photos) lives on disk keyed by listing id but is invisible to the model — so nothing can share, publish, or clean it. Sample listings get a brand-new UUID on every launch/reseed while every tool (Aerial intro on the Home tab included) is enabled on them, so AI output generated against a sample is orphaned on the next launch.

Settings/Profile has several rows that lie or do nothing: the Wi-Fi-only toggle displays ON while the upload manager reads it as OFF, "Share my portfolio (N)" counts listings the exporter will refuse and then silently does nothing, the exported "link" is an HTML file, "Delete account" for a signed-out user wipes the phone and reports "Your account and data have been removed" while hosted tours stay live, there is no sign-in/sign-out at all, and the brand-kit sync erases the hosted agent card whenever an empty per-type card editor is dismissed. The `Enhancements` model (declutter/restage) is collected, never applied by any render path, and its only effect is to stamp an untouched video "Virtually staged" on the public page.

## Findings (most severe first)

### F-C-01 · P1 · No way to delete a listing; drafts, mistakes and their media are permanent
- Where: `apps/ios/Rendprop/RendpropApp.swift:73-109` (AppModel mutation API: add/setStatus/modify/setSold/setZillow/setMainPhoto/setCoordinate — no `remove`); `Screens/HomeListingsView.swift:41-48` (no swipe/context delete); `Screens/FlythroughDetailView.swift:253-295` (Manage card: only sold/Zillow); `Screens/NewListingView.swift:297-310` (a draft listing is inserted into the model the moment the user taps Record/Upload, before any video exists).
- What's wrong: `AppModel` has no removal API, no screen offers deletion, and nothing ever deletes a listing's files (`Recordings/…`, `Imports/…`, `Photos/<id>/`, `FloorPlans/<id>*`, `aerial-<id>.mp4`, `enhanced-<id>.mp4`, `reels/<id>-*.mp4`, `preview-*.html`, the `.motion.json` sidecar). The backend already has `DELETE /listings/:id` (`services/supabase/functions/listings/index.ts:91-97`) but `APIClient` has no `deleteListing`. "Mark as sold/archived" is the only hiding mechanism, and it leaves a 1–4 GB 4K capture on disk per listing.
- User-facing effect: every abandoned New Listing (tap Upload → cancel the picker) leaves a "Not finished" card forever; a typo'd address can't be removed; storage grows by gigabytes with no way to reclaim it; the only global escape is "Delete account".
- Fix: add to `AppModel` (RendpropApp.swift, in-target):
  ```swift
  func remove(_ id: UUID) {
      guard let l = listings.first(where: { $0.id == id }), !l.isSample else { return }
      let asset = assets.removeValue(forKey: id); let tour = tours.removeValue(forKey: id)
      renders.removeValue(forKey: id); listings.removeAll { $0.id == id }
      FileStore.deleteListingFiles(id: id, asset: asset, tour: tour)   // new static in FileStore.swift
      if let sid = l.serverID { Task { try? await api.deleteListing(sid) } }
  }
  ```
  `FileStore.deleteListingFiles` removes `asset.localURL`, `asset.motionSidecarURL`, the `preview-<name>.html` beside each video, `tour.url`, `Documents/Photos/<id>`, `Documents/FloorPlans/<id>.usdz|.json|-upload.*`, `Documents/aerial-<id>.mp4`, `Documents/enhanced-<id>.mp4`, and `Documents/reels/<id>-*.mp4`. Add `func deleteListing(_ serverID: UUID) async throws` to `APIClient` (+ Live: `DELETE /listings/:id`; Mock: no-op). UI: `.contextMenu`/swipe "Delete" with confirmation on `ListingCard` in HomeListingsView and a destructive "Delete \(spaceNoun)" row in the Manage card of FlythroughDetailView (pop after delete). Also stop inserting the draft in `prepareListing()` until an asset exists, or remove it on `onDisappear` when `pendingAsset == nil`.

### F-C-02 · P1 · A listing whose render/publish was interrupted is stuck in "Working on it" forever; nothing can resume, re-render, publish, or repair it
- Where: `Screens/ReviewSubmitView.swift:337-350` (sets `.processing`, keeps `Render` only in `@State`); `Screens/RenderStatusView.swift:113` ("Keep the app open"), `:419-424` (`.ready` only on success); `RendpropApp.swift:44-63` (`load()` restores status verbatim, no reconciliation); `RendpropApp.swift:28` (`renders` is never written by any screen — grep: only `SettingsView.swift:325` clears it); `Screens/FlythroughDetailView.swift:185-203` ("Publish to get your share link" card has no button).
- What's wrong: The status machine has no recovery edge. If the app is killed (or the user backgrounds it long enough) during the on-device render or during publish, the persisted listing stays `.processing` with an asset but no tour. On relaunch the card says "Working on it", the detail screen plays the raw capture, the share card says "Create your tour and it becomes a live page" with nothing to tap, "Tag rooms" works but there is no way to reach `RenderStatusView`/`ReviewSubmitView` again, and F-C-01 means it can't be deleted either. Because `Render` (tier + enhancements) is never stored in `model.renders`, even a future "retry publish" has nothing to publish with. Symmetrically, a render that finished but whose publish failed leaves `tours[id]` set while status stays `.processing`; and an asset/tour whose file went missing (`RendpropApp.swift:274,283` drop it silently) leaves a `.ready` listing that plays the *demo* reel labelled "SAMPLE TOUR".
- User-facing effect: the user's only path is to create a new listing and re-import the same video; the stuck one stays in the list forever.
- Fix: (1) In `ReviewSubmitView.start()` store `model.renders[listing.id] = render` (already persisted by `PersistentStore`). (2) In `AppModel.load()` after restore, reconcile: `.processing`/`.uploading` → `.ready` if `tours[id] != nil` else `.draft`; `.ready` with no tour, no asset and `serverShareURL == nil` → `.draft`. (3) In FlythroughDetailView, when `asset != nil && tour == nil`, replace the inert "Publish to get your share link" card with a `NavigationLink { ReviewSubmitView(listing: currentListing, asset: asset) }` labelled "Create my tour"; when `tour != nil && serverShareURL == nil`, show "Publish tour" that calls `model.publishTour` using `model.renders[id] ?? Render(listingID:tier:.smooth…)`. (4) Optionally drop the status enum's dead `.expired`/`.uploading` cases from the UI legend (`DesignSystem/Theme.swift:70-99`).

### F-C-03 · P1 · Sample listings get a new UUID on every launch/reseed, yet every tool works on them — AI output and files generated against a sample are orphaned
- Where: `Models/Listing.swift:8` (`var id = UUID()`), `:415-476` (`sampleListings` builds fresh structs each access); `RendpropApp.swift:59-62, 68-71` (called on every `load()`/`reseedSamples()`); `RendpropApp.swift:459-460, 542-547, 688-694` (Home "Aerial Intro" tile and sheet default to `heroListing = firstRealListing ?? demoListing`, i.e. the sample when the user has no listing); `Screens/FlythroughDetailView.swift:213-249, 257-265` (Photos & AI edits, Reel, Floor plan, Aerial intro, Mark as sold all enabled for samples; only "Tag rooms" is gated).
- What's wrong: A sample is a different `Listing.id` every time the app starts or the business type is switched. Anything keyed by that id — `Documents/aerial-<id>.mp4`, `Photos/<id>/…`, `FloorPlans/<id>.usdz`, `reels/<id>-…`, `model.assets/tours`, `mainPhotoRelPath` (which `PersistentStore.save` drops anyway because samples are filtered) — is unreachable after the next launch and is never cleaned up. Marking a sample sold moves it to the Sold folder until relaunch. A new user with zero listings is steered by the Home showroom straight into generating a (server-metered, AI-cost) aerial for "1247 Hillcrest Drive (Sample)".
- User-facing effect: "I generated an aerial / scanned a floor plan / enhanced photos and they're gone"; disk fills with orphan files; AI budget spent on a demo.
- Fix: (a) Give samples stable ids: in `sampleListings` pass `id: UUID(uuidString: "00000000-0000-4000-8000-0000000000\(type-index)\(n)")!` per type/index. (b) Gate tools on `listing.isSample`: in FlythroughDetailView disable Photos/Reel/Floor plan/Aerial/Mark-sold tiles for samples with the same `dimmed:` + "Create a \(noun) first" copy the Home tiles already use (`RendpropApp.swift:708-739`); in `HomeDashboardView` change the Aerial tile to the same `goToListings()` fallback when `firstRealListing == nil`. (c) Make `AppModel.setSold/setMainPhoto/setZillow/setCoordinate/modify` no-op for `isSample` listings.

### F-C-05 · P1 · One org brand kit vs. six per-type cards: dismissing an empty per-type card editor erases the hosted agent card for every published tour
- Where: `Screens/SettingsView.swift:801-814` (`AgentCardEditorView.onDisappear` PATCHes unconditionally, even when every field is ""), `:621-625` (per-type UserDefaults keys), `:947-962` (`ProfileView.onAppear` re-pushes whichever type is current); server: `services/supabase/functions/me/index.ts:135-136,158-160` ("" → delete key from `brand_kit`), single `orgs.brand_kit` row.

### F-C-15 · P2 · Persistence: a read/decode failure of one collection wipes that whole collection on the next save; a read failure of the file would be overwritten by an empty snapshot
