# Account data export — implementation and verification handoff

The candidate now implements authenticated `GET /me/export` in `services/supabase/functions/me/export.ts` and Settings → Download account data in `apps/ios/Rendprop/Screens/AccountDataExport.swift`. Deployment and the final signed archive remain root-owned. This JSON is an account-owned cloud inventory with an explicit omissions manifest. Binary media, local files, shared team billing, experimental/transient jobs and unavailable account-wide consent evidence are excluded. Compliance CSV and Profile card/portfolio sharing remain separate.

An authenticated `GET /me/export` should return an attachment with an explicit versioned manifest, collection row counts, omitted collection/reason entries, generation time and verified actor ID. Use `Cache-Control: private, no-store` and a safe static attachment filename. Resolve the actor from verified Auth; refuse pending deletion. Enumerate all of that actor's current workspaces, independently of the selected-workspace header. Bound pages, rows, text and total encoded bytes, and fail explicitly if a complete requested inventory cannot fit rather than silently dropping rows. A collection omitted by design must be named in the manifest. A truncated inventory must not be labeled a complete account export.

Ownership is `profiles.id=actor`; `memberships.user_id=actor`; `member_portfolios.user_id=actor`; Studio `user_id`/`actor_id`/`document_user_id=actor` according to each actual schema; and listings `agent_id=actor` within a current, active workspace membership. Child listing data must join that final own-listing set. Being workspace owner/admin alone must not cause another member's private card, drafts, recordings, leads, payments or diagnostic payloads to be included. Recheck current profile/deletion status, active orgs, membership and listing assignment after asynchronous assembly; discard or refuse withdrawn collections before returning bytes.

Binary media, on-device-only unsynced files, removed-workspace data, another member's private data, server operational/security secrets and third-party data outside the actor's authority must be named as omissions. If supported, point to the separate original-media download flow; do not put long-lived or raw R2 links into the export. Audit every table's actual actor column before adding it; the table list above is a category inventory, not authorization by name.

Native entry should live in Settings' authenticated account section. Production `LiveAPIClient` already owns bounded authenticated request execution; introduce a dedicated account-export response method rather than reusing compliance or portfolio exporters. The download/share action must retain `AuthStore.userID` and `syncSessionRevision`, recheck them before creating/presenting a temporary file, write only the verified attachment to owned scratch storage, and remove stale/cancelled files. Use the established `UIActivityViewController` share wrapper with a new dedicated account-export state; never surface a prior actor's result after sign-out/account switch. Preserve user-visible failure/retry and do not claim a request succeeded until the manifest and actor match.

Minimum verification before wiring the final UI: actual handler Auth/method/actor tests; deterministic multi-page completion and explicit size overflow; foreign actor/workspace/listing and omitted-field fixtures; compiled negative controls removing actor filter or final authority fence; sign-out/deletion/removal/assignment withdrawal during assembly; native current-context vs stale download receipt and temp-file cleanup; and full platform build/real Files share acceptance. Source manifests must include the new handler, its imports, migration/RPC definitions if introduced, fixtures and native consumers.

The implemented response manifest is `rendprop-account-export-v1`, scope `current-account-owned-cloud-records`, counts for every returned collection, `truncated: false`, and explicit omissions. `complete_within_scope` describes the named returned field inventory, not every byte ever associated with the account. It identifies live assembly as distinct from a transactional database snapshot. Limits are 100 workspaces, 10,000 rows per collection, 20,000 aggregate rows, 300 inventory queries, two MiB per text value and 20 MiB encoded attachment. Heavy document/details pages contain at most five rows; other pages contain at most 100; UUID filters contain at most 100 IDs. Overflow returns 413 with an assisted-export instruction. Count/duplicate-key/access changes return 409 or account unavailability 403. Missing optional schema is named unavailable; generic DB outage returns 503. No inventory is silently truncated.

Returned collections are own profile/card; own memberships and safe active workspace fields (`effective_plan` from the existing RPC, `plan_raw` separately); own member portfolio selection; own assigned listings; their asset metadata/chapters/photos/jobs/renders/provenance/inquiries/client contacts; author-owned Studio documents/results/presenter drafts and jobs/production versions and review state; subject-owned presenter profile metadata; actor-owned project media metadata; actor-owned saved `serving_operation_results` in current own workspace scopes; own notification preferences and safe device registration metadata; actor-owned confirmed Apple subscription metadata; own lifecycle request status. Every row is projected through a field allowlist and independently checked against its query scope. Authored work for a collaborator's listing is returned for the author only after the referenced listing's current workspace/deletion check; that collaborator's facts/card/media are excluded. Provider snapshots, delivery capabilities, keys, tokens, reviewer events and operational payloads are excluded or recursively redacted, including embedded managed R2 URNs and Rendprop delivery URLs that encode storage identities. Shared usage/cost ledger is explicitly excluded because it lacks reliable account attribution; returned charges are not a complete billing ledger.

Native receipt validation checks version, actor, profile identity, generation date, scope, nontruncation and exact counts before saving. AuthStore user ID and sync session revision must remain current. Each action also owns a fresh generation UUID: a cancelled old request or an old share-sheet dismissal cannot clear a newer same-account download. Owned temporary directories use mode 0700; JSON files use mode 0600 with complete iOS file protection. Cancellation/account changes remove only the owned generation. Startup and the account-change callback remove only the export-owned scratch directory. No export bytes are cached in account storage or silently sent to a recipient.
