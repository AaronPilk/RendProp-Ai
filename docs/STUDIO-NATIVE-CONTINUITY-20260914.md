## Working continuity

| Agent workflow | Implemented handoff |
| --- | --- |
| Save a new listing on an identified iPhone account | Creates its shared server row automatically. The same local draft has one caller/workspace-bound server UUID on retries. No media upload or AI generation is triggered. |
| Edit listing details on phone | Existing dirty-write loop PATCHes the same server ID. Fields include address, space type, price, beds, baths, size, description, details, coordinates, sold status, website/Zillow URL and search indexing preference. |
| Edit listing details in Studio | Phone pulls the complete RLS-scoped listing set at launch, foreground, sign-in and pull-to-refresh. Local IDs, original files and unfinished writes survive merging. |
| Lose the reply to the first create | Server replays the same row. If the phone did not change its facts, the recovered office version wins; newer phone edits remain queued for PATCH. |
| Change accounts and return | Automatic writes stay with the draft's account. Previously bound device listings retain a detached identity, recovered only when the authorized returning account's complete cloud read includes that row. |
| Publish from either surface | Native hydration restores the actual published render ID and branded/unbranded links. Removing/revoking a cloud row hides its links and blocks automatic recreation while preserving device files. |
| Use Studio photos on phone | Listing → Cloud files previews the shared gallery and explicitly imports an image plus its actual original into native Photo Studio. Altered files without an original cannot masquerade as originals. JPEG, PNG and WebP file extensions are retained. |
| Use a shared walkthrough on phone | Cloud files previews and imports MP4/QuickTime video into the listing's existing capture/review path. Replacement of a selected local walkthrough has a confirmation. Chapter labels from the first listing-state page attach to the imported asset. |
| Use shared narration/script on phone | Cloud files reads `creative-results` and `creative:<serverListingId>`. Explicit narration import saves audio and word timings; the native Reel Studio uses it without generating again. Explicit script import becomes its AI script input. |
| Share native Reel setup | Native Reel Studio has Save setup / Load saved setup. The typed `native:<serverListingId>` document stores script, motion prompt, aspect, title card, caption switches/style, transition, tone, known narration result ID and photo order. Compare-and-swap revision prevents silent overwrite of another device's saved version. |
| Keep uploaded phone photo selections | Build 27 resolves selected photo bytes against completed upload receipts bound to owner, server listing, role, SHA-256 and byte count. The genuine `capture_assets.id` is retained across relaunches; there is no re-import/reselection step for already uploaded photos, no filename/position inference, and no additional upload. Hashing runs off the main actor with visible progress. Cloud imports retain an explicit response-ID/content receipt. |
| Continue with narration generated on phone | Successful native voice generations now enter private shared creative history when the server confirms storage and provenance. Build 27 carries the optional `shared_result_id` with the selected voice, account and listing, persists that association and includes it in Save setup. A missing history receipt never discards successful paid audio. |
| Manage enquiries | Studio searches/filters and updates the actual lead status. Phone reads fresh leads on open/foreground/refresh and displays new/contacted/won/lost. |
| Change brand/profile | Studio edits the native `/me/brand` contract. Phone pulls brand fields while protecting an unsynced local card. Existing native social handles and bare domains remain editable in Studio. |
| Change notification choices | All six categories and `muted_until` use the native backend's exact keys on both surfaces. Native master re-enable clears the mute; an expired mute does not accidentally defeat a new disable. |
| Team and plan | Studio exposes native seats, explicit email invitations, join/revoke/remove, role-aware activity and subscription management link. Native screens refresh on foreground; account changes clear visible old team/account state. |

## Deliberate limits and remaining work

- Phone camera/LiDAR capture, USDZ room geometry, local floor-plan editing, raw scan files and unuploaded originals remain device capabilities. A shared floor-plan URL can be opened from Cloud files; it is not reconstructed into a native editable room scan.
- Importing cloud files is explicit. The app does not download a whole office's videos over cellular simply because an account signed in.
- Native video import accepts MP4/QuickTime. Desktop WebM exports require compatible browser playback or conversion to MP4 before native editing. No conversion job is silently billed by this implementation.
- Native and browser editor documents are different typed formats. Native setup import provides semantic settings continuity, not a byte-for-byte AVFoundation timeline. The desktop editor's own trims, overlays, cutaways, music, transition timing and narration placement are not automatically materialized into the native render graph.
- The native Reel setup's photo IDs are cloud IDs only when a genuine shared ID is known through a completed exact-content upload receipt or scoped cloud import. Never-uploaded photos remain local. Legacy cloud imports made before content receipts may need importing again once; a UUID-shaped filename alone is not accepted as proof. The receiving device shows missing-media guidance and never guesses another image based on position or address.
- Native local aerial/drone cutaways, generated clips parked for later stitching, microphone recordings, music files, rendered local reels, local photo masks/crops/enhancement settings, capture motion sidecars, RoomPlan geometry, and pending native AI job recovery files are not uploaded by saving a setup. Extra clip count and local narration are explicit missing-media markers.
- The current native Reel setup is saved/loaded explicitly. It is not a background autosave of every slider or an automatic continuation of a running AI job. Opening/importing a saved recipe does not trigger paid work.
- Native voices generated before the shared-history release are not retroactively recovered. An optional shared-history write can fail while paid audio succeeds; that audio remains playable on the original device, but its missing cloud reference is not fabricated.
- Native brand is organized around the account's default workspace and business type; Studio has explicit workspace selection. Complete remote listing hydration spans RLS-authorized memberships, but a complete native workspace-selection UX remains separate work.
- Local draft facts use last-writer behavior once bound. They do not provide a field-by-field conflict editor. In-flight local dirty state is retained, and saved editor/setup documents use revision conflicts.
- Gear is not fabricated: the existing remote catalog is disabled/empty. A complete live storefront needs an enabled catalog. Platform-owner operational consoles are separate from the agent/business workspace.

## Protocol and release notes

- Listing pull: paginated `rest/v1/listings` + published `renders`, caller JWT/RLS, exact count/range checks, bounded pages. A partial/error response never becomes an empty complete library.
- Media: `GET /studio/media`, `GET /studio/listing-state`; explicit org/listing selection. Signed capability URLs are checked for canonical R2 storage, scope and expiry, and downloads carry no Supabase bearer/cookies or redirects.
- Creative: `GET /studio/creative-results`; saved script from `GET /studio/documents?key=creative:<id>`.
- Narration cleanup: before paid provider dispatch, the service reserves its exact private `ai-voice/<org>/<id>.mp3` key with an immutable 15-minute write deadline. Account deletion inventories reserved keys even when creative-history saving failed, waits until the deadline plus one hour, and retains shared-workspace keys until that workspace's final member leaves. Optional history persistence is bounded; missing history never substitutes a fabricated cloud reference.
- Native setup: `GET/POST /studio/documents`, key `native:<id>`, kind `native`, revision-controlled; payload type is `NativeReelDraft.swift`. No signed URLs or local filesystem paths are persisted.
- New draft key: `Idempotency-Key: listing-create:<local UUID>`. The `/listings` backend derives a UUID from caller, workspace and local draft, inserts with the caller-scoped client, and reads only the same caller/workspace's live row on duplicate. It never updates an existing row during replay or revives deletion. Other legacy keys/no-key requests retain their previous behavior. `create_replayed` response metadata lets native recover the correct facts after an interrupted create.
- Native version: `MARKETING_VERSION = 1.0.3`, `CURRENT_PROJECT_VERSION = 27`; the signed archive and App Store Connect prerelease version agree. `xcodegen generate` includes all new Swift sources in the standard project. `SharedVoiceReference` is an optional extension to the native Voiceover contract; existing initializer call sites continue unchanged.
