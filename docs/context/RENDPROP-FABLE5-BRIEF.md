## 0. WHAT WE'RE BUILDING

**Rendprop** — an iOS app that turns a phone walkthrough video into a smooth, scroll-through "drone-style" cinematic tour with a shareable link. Point your phone, walk the space, upload → we render a buttery glide the viewer *scrolls* through on their phone, tap dots to jump between areas, and a lead-capture end-card converts them.

**THE BIG DIRECTION (most important thing to internalize):** Rendprop is **NOT real-estate-only**. It must work for ANY business — event venues, restaurants/bars, retail/grocery, gyms/studios, and more. And it can't just swap words. **Each business type must feel like a genuinely different app** — different home screen, icons, sample content, fields, and call-to-action. When a user picks "Event venue," nothing on screen should scream "house." That's the current mission and where the last session left off (see §7).

## 1. OPERATING CONSTRAINTS (READ — these are hard-won, ignore at your peril)

1. **You CANNOT compile Swift in this sandbox.** Write clean code, then **verify with a subagent** (spawn a general-purpose agent to do a static compile-audit of changed files). The audit has caught real bugs every time (e.g. `==` on a non-Equatable enum, `Substring ?? String` mismatches). Always audit big changes before handing back.
2. **New `.swift` files often DON'T get added to the Xcode target** (the project is generated by XcodeGen; a stale project silently drops new files → "Cannot find X in scope" build failure). **RULE: put new types/views inside EXISTING in-target files** (append to the relevant screen/model file). Only create a new file if you also tell the user to run `xcodegen generate` before building. This has burned us twice — respect it.
3. **Git push happens from the user's Mac, not here.** After changes, give the user a `git add -A && git commit -m "..."` command. Do NOT commit from the sandbox (it leaves lock files that break their git). If you see stale `.git/*.lock`, tell them to `rm -f .git/HEAD.lock .git/index.lock` on their Mac.
4. **New model fields MUST be Optional** (`Date?`, `String?`, `[String:String]?`) — Swift's synthesized `Decodable` throws on missing keys for non-optionals, which would wipe the user's saved data on upgrade. Optionals decode to nil. Never add a non-optional stored property to `Listing`.
5. **Navigation must be destination-based**, never value-based `NavigationLink(value:)` + shared `navigationDestination(for: Listing.self)` — that caused a multi-push bug (stacked detail views, 20 back-taps, WKWebView process flood). Use `NavigationLink { Destination } label: {}`.
6. Deployment target **iOS 16, Swift 5.9**. `.onChange(of:)` uses the single-param iOS-16 form. `TextField(_:text:axis:)`, `.lineLimit(2...4)`, `Map(coordinateRegion:...)`, `PhotosPicker`, `RoomCaptureSession` all iOS 16+.
7. **Benign Xcode log noise to IGNORE:** `web-browser-engine.*` entitlement errors, `default.csv`, `RBSRequestError`, `Hang detected (debugger attached, not reporting)`, gesture-recognizer-dependency warnings. These are WKWebView/system noise, not our bugs.
8. Use **subagents in parallel** for research and verification (they don't touch files → no conflicts). Do NOT run parallel agents that edit the same Swift files — they clobber each other. Coordinated code edits = do them yourself sequentially.

## 3. WHAT'S ALREADY BUILT (all shipped, on device)

- **Persistence:** `PersistentStore` saves listings/assets/tours/renders to `Documents/rendprop-state.json`; `AppModel` restores on launch + auto-saves on every mutation (didSet). File URLs stored RELATIVE to Documents (container path changes across launches) and rebuilt on load.
- **Capture:** upload-first (primary) + in-app record (secondary). Both feed the same pipeline.
- **Render engine v2:** on-device. Retime (2× walk glide), Vision translational stabilization (measures jitter → Gaussian-smooths the camera path → per-frame correction + adaptive crop), 60fps, **ALL-INTRA H.264** (every frame a keyframe → buttery scrubbing), HDR→Rec.709 SDR, graceful fallback if stabilization is low-confidence. Drone clips skip stabilization.
- **Scroll-scrub player** (`Resources/player/index.html`): rAF lerp scrub, buffer gate, clickable chapter rail (tap a dot → seek to that area), lead-capture end-card with agent card + CTA, jank watchdog. Tuned PX_PER_SEC/LERP for a controlled glide.
- **Room/area tagging:** live during capture AND scrub-and-tag after upload (`RoomTaggerView`). Tags → the player's jump dots. Tag names adapt to business type.
- **Photos → pro listing images:** `PhotoStudioView` + deterministic Core Image `PhotoEnhancer` (shadow lift, vibrance, contrast, sharpen — free, on-device). Multi-import + camera, before/after compare, share export, per-listing files. **Set a main image** (long-press → star) → shows as the card hero.
- **Floor plan (LiDAR):** Apple RoomPlan scan → USDZ export → QuickLook viewer, gated by `RoomCaptureSession.isSupported` (Pro devices).
- **Geolocated map:** CLGeocoder on the address → MapKit map on the detail; "Use current location" in New Listing (reverse-geocode + set coords).
- **3-tab bar:** Homes / Profile / Settings.
- **Agent/owner card:** name, brokerage/business, phone, email, website, **headshot** (PhotosPicker, base64-embedded into the tour), Instagram/LinkedIn/TikTok. Injected into the tour end-card (name, initials/photo avatar, social links, CTA).
- **Mark as Sold / Archived → folder** (adapts label per type). **Zillow / listing link** per listing.
- **Portfolio share:** `PortfolioExporter` builds a self-contained HTML page of all active listings (photos embedded, tour links, agent header) → shared via `ShareSheet`. (An HTML file today; becomes a hosted URL with the backend.)
- **Multi-business `SpaceType`:** realEstate/venue/restaurant/retail/fitness/other. Picker in onboarding + Settings (top, inline). Adapts collection title, "New ___" button, area tags, CTA, sold→archived label, "Brokerage"→"Business".
- **Per-industry DATA (data-driven fields):** `SpaceType.detailFields` defines each type's owner inputs (typed: text/number/price/priceRange/hours/multilineText/toggle/url/singleSelect/multiSelect). `DetailFieldsEditor` renders the right control per field. Values → `Listing.details [String:String]`. Detail screen shows a "Details" card; URL fields (reservations/booking/online-store/website) become tappable CTA/action buttons via `SpaceType.actionURLKey`. **Spec is locked in `docs/INDUSTRY-LOGIC.md`.**

## 4. RENDER ENGINE NOTE

`Render/RenderEngine.swift` is a two-pass AVFoundation pipeline. Encode is now all-intra (`AVVideoMaxKeyFrameIntervalKey: 1`, bitrate 14M) for scrub smoothness — files are larger; when the backend exists we'll generate a lighter streaming proxy separately. Stabilization is Vision-based and best-effort. It's slightly shaky still on rough footage — improving stabilization quality is a known backlog item (consider gyro-sidecar fusion; a 100Hz motion sidecar is already captured in `MotionRecorder`).
