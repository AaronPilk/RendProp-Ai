# Presenter execution RPC protocol

This protocol is offline implementation behind disabled runtime gates. It does not establish an enterprise contract, a current provider price, an actual-cost reconciliation API, or production activation. USD values are integer cents. The spatial experiment budget is unrelated.

## Runtime and financial authority

`studio_presenter_runtime` is service-managed only: `org_id`, auto-incrementing `revision`, `enabled` (false), `enterprise_no_training_confirmed` (false), `contract_reference` (empty), `price_version` (empty), `max_job_cents` (0), `total_budget_cents` (0). No row is created automatically. The total is a lifetime allocation for this workspace's Presenter jobs, not a monthly allowance. Increasing it requires the owner's authorization.

The authenticated provider estimate is `quote_cents`; it is not represented as guaranteed billing. `max_cost_cents` is the separately configured conservative per-job hold. The contract must support that bound before activation. Jobs reserve the full maximum, not merely the estimate. Holds plus confirmed spend consume the workspace budget. Unknown or ambiguous billing stays held. Settlement requires `billing_final:true`, nonnegative `charged_cents`, and a nonempty durable `billing_reference`. A provider failure alone is not a refund. Charges exceeding the authorized hold are recorded honestly and disable subsequent generation.

## User-scoped service RPC

`studio_presenter_execution(p_actor uuid, p_org_id uuid, p_listing_id uuid, p_action text, p_payload jsonb)` is callable only with the service role. The Edge supplies its verified actor and org, never client actor fields. Every call checks named active account, membership, workspace and property. Public responses must be projected; never return raw worker objects.

- `quote_prepare`: `{draft_id, expected_revision, expected_profile_revision}` → private `{snapshot,source_asset,reference_assets,runtime,price_version,max_cost_cents,execution_spec}`. Controller validates immutable source/reference bytes and measures the video before requesting the authenticated provider estimate.
- `quote_commit`: same identity fields plus `{quote_id,quote_cents,price_version,execution_spec,probe:{sha256,bytes,duration_s}}` → `{quote,runtime}`. The digest/bytes must equal the approved original; measured duration must be 4–30 seconds. Quote expires after five minutes and binds approval snapshot, measured input, runtime revision and price version. Client amounts/probes are never forwarded directly.
- `create`: `{quote_id,idempotency_key,cost_consent:true,max_cost_cents}` → `{job,replayed,runtime}`. Exact maximum consent is required. One quote creates one durable job, including across different request keys. A matching request key recovers its existing job. Budget reservation and creation occur under the workspace lock before any provider dispatch.
- `get`: optional `{job_id}` → `{org_id,listing_id,runtime,quotes,jobs,truncated}`. Both arrays are capped at 100, newest first. Quotes are only the caller's unexpired unconsumed quotes. Expired snapshots are deleted.
- `cancel`: `{job_id,expected_revision}`. Before dispatch, cancels and releases the unspent hold. After dispatch, persists `cancel_requested` and keeps the hold pending confirmed outcome/billing.
- `preview`: `{job_id}` → private `{job,output_key,sha256,bytes,duration_s}`. Only the subject can preview `review`; members may preview accepted output. Controller signs a short private URL, then revalidates before returning it.
- `accept`: `{job_id,expected_revision,output_sha256,output_consent:true}`. Only the represented subject can accept the exact immutable generated bytes.
- `reject`: `{job_id,expected_revision}`. Only subject; rejects review/accepted/importing/imported output, denies new access, retains denied capture/provenance identity rows, clears the provenance output link, and queues storage cleanup. Does not invent a refund.
- `import_prepare`: `{job_id,expected_revision}` → private `{job,output_key,sha256,bytes,duration_s,import_asset_id}`. Requires current accepted exact output. Existing upload endpoint supplies native quota/reservation and immutable operation transport. Controller binds the reserved asset before PUT and always resumes that same asset ID.

Job DTO includes `id,org_id,listing_id,draft_id,profile_id,subject_user_id,requester_user_id,draft_revision,profile_revision,quote_id,idempotency_key,status,state,revision,quote_cents,max_cost_cents,held_cents,charged_cents,currency,output,imported_asset_id,created_at,updated_at,permissions`. `output` is null or `{sha256,bytes,duration_s}`; it has no URL. `permissions` includes `can_cancel,can_preview,can_review,can_accept,can_reject,can_import`. Scalar revisions survive privacy scrubbing. No provider reference or storage key appears in a public DTO.

## Worker-only RPC

`studio_presenter_execution_worker(p_job_id uuid, p_action text, p_payload jsonb)` is service-only. User-controlled action names/payloads never directly call it. Return values contain private durable job fields.

- `read` (alias `get`): `{}` → `{job,allowed,snapshot,probe,source_asset,reference_assets,runtime}`. Invalid consent/source/account is fenced and queued for cleanup.
- `dispatch_prepare`: same return; `allowed` only when reserved, valid and runtime enabled. Revalidate actual input bytes before claim.
- `dispatch_claim`: `{}` → `{claimed,job,dispatch_token?,snapshot?,probe?,output_key?}`. **Exactly one claim for the job's entire lifetime.** A stale request, timeout or crash never reopens dispatch. Only `claimed:true` permits one provider POST. A global advisory lock limits Presenter claims across workspaces to three unfinished provider requests; unresolved acceptance continues to consume that capacity.
- `dispatch_result`: `{dispatch_token,request_id,status_url,response_url?,cancel_url?}`. Requires claim token. Provider refs are immutable once recorded; recording a late accepted response preserves cancellation/invalidation state.
- `ambiguous`: `{dispatch_token}`. Persist uncertain; no refund or retry of POST.
- `status`: `{state:'queued'|'processing'}`. Cannot resurrect cancelled/rejected/invalidated/accepted output or regress processing to queued.
- `output_claim`: `{}` → `{claimed,job,lease_token?,write_deadline?,output_key?}`. Only valid live provider jobs; five-minute bounded write lease. Controller must not start/continue storage writes beyond it; retry must verify existing immutable bytes rather than overwrite a reviewed output.
- `output_ready`: `{lease_token,sha256,bytes,duration_s}` after actual private MP4 storage. Max 48 MiB, measured duration 1–31 seconds. Current lease/consent required; existing digest/size/duration cannot change. State becomes `review`, with no generic creative history or uploaded capture asset.
- `settle`: `{billing_final:true,charged_cents,billing_reference}`. Confirmed billing only. Unknown billing retains its hold. Settlement is immutable/idempotent for identical evidence.
- `failed` / `cancelled`: optional confirmed billing fields as above. Without them terminal status is persisted but the hold remains. No arbitrary transport failure supplies final billing.
- `import_bind`: `{asset_id}`. Only after subject acceptance and native upload reservation; verifies exact listing/type/bytes/current reservation, marks `capture_assets.presenter_job_id`, and fixes the expected SHA. A different asset cannot replace an existing import. Controller then streams the accepted bytes through existing upload transport.
- `import_commit`: `{}`. Requires completed exact marked asset and disclosure. Publication trigger rechecks active consent and bytes before completion; no generic creative dispatch or import is involved.
- `cleanup_claim`: `{}` → `{claimed,job,cleanup_token?,targets?:[{bucket:'uploads'|'renders',key}],request_id?,cancel_url?}`. Waits until private output write deadline plus one minute; five-minute cleanup lease. Native upload operation cleanup separately owns temporary copy/multipart objects.
- `cleanup_done`: `{cleanup_token,objects_deleted:true}` after confirmed deletion. Scrubs snapshots but preserves financial/provider/key tombstone. Never releases an uncertain paid hold.

`studio_presenter_execution_due(p_limit integer=50)` → `{jobs:[{id,state,cleanup_state}]}`; bounded 1–100. Deletes expired quotes and converts dispatching older than two minutes to uncertain. It never retries a provider POST. Worker `sweep`/`drain` aliases provide the same bounded inventory at 50.

## Privacy and deletion

Ledger rows deliberately have no cascading identity, profile, property or workspace foreign keys. Source/profile/draft/account/membership invalidation scrubs snapshots, invalidates approval, retains inaccessible marked capture/provenance rows for native/reflection foreign keys and clears their provenance output links, and queues owned output keys. Quotes have no financial value and are deleted on invalidation, expiry and identity deletion, including quote-only accounts. Undispatched jobs release zero-spend holds; dispatched jobs retain their hold until confirmed billing even after all represented users are deleted.

`capture_assets.presenter_job_id` links only an accepted output import. `studio_presenter_asset_access(p_asset uuid) -> boolean` checks current consent/identity/input binding. The recursive media predicates below cover this marker and declared edit/reflection descendants. `assert_studio_asset_quality` wraps the existing quality checks with that recursive guard, so native publication and recursive edited-source checks enforce current Presenter acceptance. Presenter markers cannot be stripped and imported presenter clips cannot be used as original likeness/reference candidates.

Revocation denies newly issued access. Previously issued short signed URLs can remain valid until expiry, and already downloaded or externally published copies cannot be recalled. Generated provider objects require the provider's actual retention/deletion contract; local object cleanup does not establish provider deletion.

`close_submission {quote_id,idempotency_key}` runs under the same current-clock lock as create. It recovers an existing durable job or records a scalar closed-submission tombstone and deletes the caller's unused quote, preventing a delayed request from spending later. `completed {}` independently records known provider completion even after cancellation/invalidation, freeing provider concurrency without inventing a refund. Maintenance stamps returned rows for fair bounded rotation, and keeps invalidated known provider requests in polling inventory until terminal. Execution specifications are stored separately from the recording guide, copied verbatim from quote to job, and never replaced by a later helper default.


## Existing media capabilities after revocation

The additive media migration exposes authenticated/service-only boolean predicates `studio_presenter_media_access(p_asset uuid)`, `studio_presenter_render_access(p_render uuid)` and `studio_presenter_key_access(p_listing uuid,p_key text)`. They require an active property/workspace; authenticated requests also require membership. No private job or provider details are returned. The internal traversal follows at most 200 unique source identities, terminates cycles, and fails closed on oversized/malformed source graphs. Ordinary recorded media keeps its existing read behavior.

`studio_presenter_media_visibility(p_listing uuid,p_assets uuid[],p_renders uuid[],p_keys text[])` returns `{assets:{[id]:boolean},renders:{[id]:boolean},keys:{[key]:boolean}}`. Arrays default empty, have no null members and contain at most 200 combined entries. Every ID/key is scoped to this exact property, including when a member can access another property in the same workspace. Historical noncanonical upload/render keys require an exact existing property capture, render or provenance record; unknown legacy keys and foreign canonical keys remain denied. URL-producing handlers also retain their independent canonical bucket/key scope checks. Read handlers must validate both row identities and actual keys before signing and revalidate those same capabilities before responding; lookup failure denies fresh URLs. The shared handler helper splits bounded pages into batches.

Restrictive authenticated SELECT policies cover capture assets, native renders and provenance media links. Service tours, native render status and Studio media/creative paths invoke the batch gate explicitly. The native create/publish idempotent replay paths recheck consent. Reflection reserve/status/acceptance recheck source ancestry; a late provider completion still settles accounting but its returned revoked output URL/key is redacted. Brokerage audit exports and label-only provenance edits preserve disclosures while removing inaccessible keys from their returned data.

`studio_presenter_media_sources` retains only declared child/source UUIDs, property ID and the already-owned storage key. It has no cascading capture or author FK: deleting result history, an editor account, a reflection batch or an intermediate source cannot detach retained shared media from the revoked origin. Property deletion removes these edge records. They are recorded from trusted Studio result/reflection transactions and backfilled for existing declared edits; this does not identify undeclared edits or certify final pixels/audio. No new job engine, provider request or budget is introduced by these media guards.
